# Content Creation Guide

Complete guide for creating and managing articles on edgar.barrantes.dev.

## Quick Start

### Creating a New Article

**Thoughts** (long-form articles, essays, book reviews):
```bash
npm run new:thought "Your Article Title"
```

**TIL** (Today I Learned - quick technical notes):
```bash
npm run new:til "What You Learned"
```

This will:
- ✅ Create a new markdown file with proper frontmatter
- ✅ Generate a URL-friendly slug
- ✅ Set today's date automatically
- ✅ Open in your editor (if `$EDITOR` is set)

## Article Structure

### Frontmatter (Required Metadata)

All articles require YAML frontmatter at the top:

```yaml
---
tag:
  - category-1
  - category-2
  - technology-name
title: "Your Article Title"
description: "One-sentence summary for SEO and previews (140-160 chars ideal)"
date: "2025-01-15"
---
```

#### Fields Explained

- **tag**: Array of tags for categorization and filtering
  - Use kebab-case (lowercase with hyphens)
  - Examples: `typescript`, `web3`, `blockchain`, `book-review`

- **title**: Article title (used in SEO, og:title, page title)
  - Keep concise but descriptive
  - 50-60 characters ideal for SEO

- **description**: One-sentence summary
  - Appears in search results, social shares, article listings
  - 140-160 characters ideal
  - Should be compelling and clear

- **date**: Publication date in YYYY-MM-DD format
  - Auto-generated by creation script
  - Used for sorting and display

### Content Guidelines

#### Thoughts (Long-form)

Structure for thoughtful, in-depth articles:

```markdown
# Article Title

## Introduction
Brief overview of the topic

## Main Content
### Subsection 1
### Subsection 2
### Subsection 3

## Key Takeaways
- Point 1
- Point 2
- Point 3

## Further Reading
- [Resource](https://link.com)
```

**Best Practices:**
- Aim for 800-2000 words
- Use clear headings (H2, H3)
- Include code blocks with syntax highlighting
- Add external links for references
- Include a summary or key takeaways

#### TIL (Quick Notes)

Structure for quick technical notes:

```markdown
# What You Learned

## Problem
What situation led to this learning

## Solution
```bash
command-or-code-here
```

## Explanation
Why it works, gotchas, important details

## References
- [Docs](https://link.com)
```

**Best Practices:**
- Keep it focused and concise (200-600 words)
- Always include code examples
- Link to official documentation
- Mention version numbers if relevant

### Code Blocks

Use fenced code blocks with language specification for syntax highlighting:

\```typescript
const example: string = "Hello, World!";
console.log(example);
\```

Supported languages: `typescript`, `javascript`, `bash`, `python`, `rust`, `solidity`, `cairo`, etc.

### Links and Images

**External Links:**
```markdown
[Link Text](https://example.com)
```

**Images:**
```markdown
![Alt text](/path/to/image.jpg)
```

## File Organization

```
content/
├── _thoughts/           # Long-form articles
│   ├── article-slug.md
│   └── another-article.md
└── _til/                # Quick technical notes
    ├── til-slug.md
    └── another-til.md
```

### Naming Convention

Files are automatically named using slugs (URL-friendly versions of titles):

- Original: "Setting Up SSH Keys on GitHub"
- Slug: `setting-up-ssh-keys-on-github.md`
- URL: `/til/setting-up-ssh-keys-on-github`

**Rules:**
- Lowercase only
- Replace spaces with hyphens
- Remove special characters
- Keep descriptive but concise

- ✅ Auto-generated in `/rss.xml`

- ✅ Updates on build

- ✅ Auto-generated in `/sitemap.xml`
- ✅ Includes all published articles

- ✅ Updates on build

## Workflow

### 1. Create Article
```bash
npm run new:thought "My New Article"
# or
npm run new:til "Thing I Learned Today"
```

### 2. Write Content
- Edit the generated markdown file
- Follow structure guidelines above
- Add your tags in frontmatter
- Write clear, concise content

### 3. Preview Locally
```bash
npm run dev
```
Visit `http://localhost:3000`

### 4. Build & Test
```bash
npm run build
```
This will:
- Generate static pages
- Create sitemap
- Generate RSS feed
- Show any build errors

### 5. Deploy
```bash
git add .
git commit -m "Add: [article title]"
git push
```

## Troubleshooting

### Article not showing up?
1. Check frontmatter is valid YAML
2. Ensure file is in correct directory (`content/_thoughts/` or `content/_til/`)
3. Run `npm run build` to regenerate static pages
4. Clear `.next` cache: `rm -rf .next`

### Build errors?
1. Check for syntax errors in markdown
2. Validate frontmatter (proper YAML format)
3. Ensure all required fields are present
4. Check for unescaped special characters

### Images not loading?
1. Place images in `/public/images/`
2. Reference as `/images/filename.jpg`
3. Use relative paths from public directory
